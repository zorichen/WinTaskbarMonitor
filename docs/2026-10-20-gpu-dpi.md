# 2026-10-20 外接 GPU、右键菜单与温控曲线

状态：本地开发版，基于 `41470b1`，分支 `codex/egpu-temperature-menu-dpi`。后续按用户授权原地更新了当前电脑，用户确认“菜单尺寸正常了，我已经验收”；未发布 Release、未修改风扇策略。用户确认原需求中的“邮件浮层”指右键菜单。下方开发阶段记录保留原验证边界，最新部署结果见文末。

## 实现与依据

- [Sensors.cs](../Sensors.cs)：增加 GPU 核心温度、占用率、设备标识与全部适配器读数；只接受 `GPU Core` / `GPU` 核心温度，排除热点及显存温度。NVIDIA / AMD 优先于 Intel，再按可用温度、温度高低和稳定标识选择。此处是厂商规则，不声称识别了 PCIe 拓扑或所有独显/核显组合。
- GPU 组在采样线程中每隔至少 30 秒重新打开，下一轮采样执行；右键可请求重新检测。CPU/磁盘组保持打开。快照过期后清空 GPU 汇总和各设备读数。外接设备断开时，驱动缓存可能在重新枚举前保留上一次温度。
- [Program.cs](../Program.cs)：发现支持的 GPU 后改为两行三列，否则两行两列；详情显示每块 GPU 的名称、标识和读数。没有核心温度的核显仍会显示 GPU 列，温度为 `—`。
- [build.ps1](../build.ps1)、[AssemblyInfo.cs](../AssemblyInfo.cs)、[app.manifest](../app.manifest)：原代码只调用 Win32 DPI awareness，未开启 .NET Framework 的 WinForms 高 DPI 功能。现在声明目标框架 4.7.2，保留供应商程序集重定向并生成 `DpiAwareness=PerMonitorV2` 配置，由 WinForms 初始化；菜单使用系统菜单字体与自动尺寸，不手工重复乘缩放。

Microsoft 文档要求 .NET Framework 4.7+ 应用选择启用高 DPI 功能；配置与旧 manifest DPI 声明不应混用。此次修正遵循该初始化路径，但没有对旧安装做相同截图条件的 A/B 对比，不能把全部历史菜单异常都归为同一个原因。

## 风扇温控曲线调研结论

### RTX 4070：有实现路径，尚未验收写入

本机只读枚举得到两路 LHM `IControl`，报告的软件控制范围为 30–100%。可以在后续功能中使用支持的驱动接口，在软件循环里把温度映射为风扇百分比；这通常不等于把一条永久曲线写入显卡固件。

LHM 的 NVIDIA 实现提供软件控制和恢复默认控制的逻辑；使用默认空设置时模式为 `Undefined`，本次仅读取传感器，没有调用 `SetSoftware` / `SetDefault`。显示 0 RPM 是当时的读数，不证明软件模式允许设为 0%。

NVIDIA NVML 也有 `nvmlDeviceSetFanSpeed_v2` 与 `nvmlDeviceSetDefaultFanSpeed_v2`。文档说明设置转速会进入手动策略，调用方必须监测温度并在需要时恢复默认。是否在这张卡、当前 Windows 驱动和权限组合上可写，必须实测返回值及实际 RPM，不能由函数存在直接推定。

来源：[LHM Control.cs](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Control.cs)、上方 NvidiaGpu.cs、[NVIDIA NVML Device Commands](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceCommands.html)。

### GTi 主机：目前支持状态未知

本次 LHM 能识别主板，但未枚举出主板 Fan / Control 传感器。由于进程不是管理员，且 CPU / 磁盘温度同时不可用，此结果不足以证明主板不支持。下一步应以管理员权限运行同一只读探测；若仍无接口，再核对准确主板/BIOS 版本及厂商支持的调速途径。本次没有找到可确认适用于当前主板的官方 Windows 调速 SDK。

[Fan Control 官方仓库](https://github.com/Rem0o/FanControl.Releases) 可作为现成能力对照，其硬件后端和插件支持列表不能替代本机验证。不根据相近型号的 EC 寄存器或 BIOS 菜单推测本机可写地址。

### 后续实现建议（未执行）

1. 先完成单风扇、可恢复的写入与 RPM 回读测试，记录每张卡的实际范围；GPU 与主板分别建立能力表。
2. 曲线按稳定设备身份绑定，不能把 `/gpu-nvidia/0` 序号当作永久身份；显卡重排或热插拔后重新确认匹配。
3. 支持温度点线性插值、迟滞与变化速率限制；范围从设备读取，不硬编码“支持停转”。
4. 进入调速前确保恢复默认策略可用；传感器过期、设备丢失、退出/休眠时恢复自动。崩溃与强杀需要独立监督机制，单靠 `finally` 不能保证恢复。
5. 避免与其他调速程序同时控制；先完成真实故障与恢复验收，再考虑默认开启。监控组件继续默认只读。
